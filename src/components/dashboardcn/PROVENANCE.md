Registry npm dependencies are bare names without version pins. The upstream docs site's [package manifest](https://github.com/NoahGdev/dashboardcn/blob/main/apps/web/package.json) uses React/React DOM `^19.2.8`, Recharts `^3.10.1`, Tailwind `^4.3.3`, Radix UI `^1.6.7`, and lucide-react `^1.39.0`; these describe that site, not a promise about dependency resolution from a future CLI command. Our Vite/React 19/Tailwind 4 project already supplies React, `cn`, and the imported Skeleton. The adapted four components add zero dependencies and no Next.js or analytics runtime. Existing shadcn files, aliases, package files, lockfiles and theme variables remain unchanged.

Modifications are deliberately narrow. Imports use the local namespace and existing `cn`; native strings such as `—`, `2+`, and preformatted duration labels render unchanged. Numeric values use unabridged Uzbek formatting with finite-value guards and 21 significant digits so a small positive value is not rounded to zero. KpiCard preserves Home's accepted compact label/value/loading structure inside the enclosing full-cell link instead of introducing another card surface. MetricList uses semantic list items and the existing inline status swatches. The copied delta, currency, compact-tooltip and sparkline features are omitted because they do not have a validated current-data use here; no `format.ts`, delta badge or chart helper is installed.

Timeline retains ordered-list, item, rail, marker, connector, content and time primitives, with styles adjusted to the accepted neutral event rail. Its connector ends at the final item. Event selection stays on the existing button's `aria-pressed`; selecting an old event does not set `aria-current` or imply current execution. The event timestamps gain machine-readable UTC `dateTime` attributes, while the existing configured-zone visible time, ordering, filtering, freshness, as-of boundary, gap handling and exact duration/endpoint computation remain in the unchanged manufacturing adapter and `railInterval` logic. No clocks extend stale histories and no animation claims telemetry.

The CLI's official [installation documentation](https://dashboardcn.com/docs/installation) states that it copies source files, installs npm dependencies and resolves required shadcn components. Reviewed payloads also include transitive presentation files such as `sparkline.tsx`, `delta-badge.tsx` and `format.ts`. Manual adaptation avoids executing a moving `shadcn@latest`, introducing unrelated registry files, replacing existing shadcn styling, or pulling chart dependencies solely for absent optional data. Native request/permission/receipt logic is outside these presentation components.
