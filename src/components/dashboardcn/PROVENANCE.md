Local source changes are narrow and visible in the diff:

- All copies receive the retained attribution/pin header and point `cn`, sibling dashboardcn helpers and shadcn imports at existing local namespaces.
- KpiCard adds only a native loading Skeleton, value identity/class hooks for existing accessible full-cell links and density, and disables automatic abbreviation at that callsite. Its full Card hierarchy and optional delta/trend public APIs remain. Real application callers supply neither delta nor trend because those facts are not available.
- MetricList accepts readonly supplied facts and disables abbreviation at its value callsite. Its original row, icon, optional Sparkline/DeltaBadge and value-column layout/API remain.
- MetricValue retains the original formatting/tooltip API, with an early finite-value guard. The format helper defaults to Uzbek formatting and preserves up to 21 significant digits when no explicit precision is requested so small positive native quantities do not become zero. No application calculations are moved into it.
- DotPlot's default numeric formatter is localized. Its original core/API are unchanged: the apparatus adapter configures the existing `max` and `rows` props to sixteen, preserving raw native integer counts while obtaining one dot per apparatus up to a disclosed sixteen-dot cap. The adapter aligns fixed-size dots and their category buttons on the same four equal grid tracks. The exact full bin counts, per-apparatus rows, unknown exclusion and loaded/partial scope remain visible. PeriodTabs and Timeline core markup/styles/public APIs are unchanged apart from imports and attribution.
- Heatmap accepts null/missing/invalid cells as unknown, excludes them from the color maximum, renders their neutral dashed outline and unknown tooltip/name, and localizes default legend labels. Known absence remains visually separate. Its matrix, label, button, focus/pointer and Tooltip structures remain intact.
- ComposedChart's original Recharts/shadcn structure and existing public API are preserved; one optional `tooltipValueFormatter` extension formats exact recorded values independently of rounded axis ticks. The application supplies only bar/line series with explicit existing neutral colors and disables animation. Unobserved date values are null; they are not replaced with zero. The existing upstream tooltip renderer uses this formatter when supplied, preserving exact seconds while axis ticks stay scaled to apparatus hours. A regression test exercises the actual tooltip callback with 1-, 7- and 17-second inputs.

The new `dashboardcn-analytics.ts` view adapter consumes existing resource rows, the existing read-only production snapshot, and existing `ManufacturingTimeline` output. It makes no requests and reads no wall clock. Apparatus queue rows join only loaded canonical apparatus IDs to their own `visible_order_ids` entries. Missing keys, malformed arrays, duplicate apparatus identities, duplicate/blank/non-string order IDs stay unknown and are excluded from the queue distribution. Only a valid native empty array establishes zero. Known counts from a retained stale snapshot remain visible with an explicit retained-state qualifier and fetch observation time; they are not described as current work. Queue counts do not infer elapsed waiting time.

The materials matrix uses the complete native `CalculateMaterial.variants` arrays supplied by the existing full materials endpoint. Valid positive integer `micron` fields within the native u32 range establish sorted real columns. A valid complete array establishes zero for an absent variant; missing/malformed/duplicate-identity or duplicate-micron arrays establish null across that row. Matrix rows are limited to eight and columns to twelve, with omissions disclosed. The matrix means catalog variant configuration, not stock availability, and does not duplicate a material variant-count list.

The production-time chart accepts only closed-order intervals whose saved start/end event IDs, timestamps, stage keys and states match, whose bounds are positive and at/before fetch as-of, and which do not overlap a recorded gap. Period clipping does not extend an interval. Per-apparatus overlapping intervals are unioned per state, so parallel/sibling records do not double-count that apparatus's same-state duration. Dated chart sums are explicitly apparatus time across the retained observed cohort; process/pause are separate series, not a claimed whole-factory clock. Date bins use the same established app/browser-user IANA zone as the production page and are limited to sixteen. No stored app timezone setting exists in the current web source; the existing `manufacturingTimeZone()` browser-user resolver supplies that zone explicitly to the pure view adapter. Actual local calendar boundaries are resolved through Intl rather than adding fixed 24-hour offsets, preserving 23-/25-hour and half-hour DST dates, fractional offsets and skipped civil dates. Record durations remain Unix-second differences and unioned per apparatus; repeated/skipped local clock readings do not change elapsed seconds. Invalid supplied zones stay visibly unknown and produce no date geometry. The chart labels its IANA zone and retained coverage, and formats fetch observation time in that same zone. Pure helper tests supply an explicit zone; the deployed page supplies its resolved user zone. Closed-order detail reuses the existing validated timeline builder and event rail through the root-owned native saved-row adapter. The existing API, permissions, lock, manufacturing adapter and receipt/calculation code are unchanged by these ports.
