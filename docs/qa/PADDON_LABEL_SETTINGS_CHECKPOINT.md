# Paddon QR labels and ordinary free-movement settings

Based on `8d69e61123e28183c44f95acbe27e9f466687e32` in the isolated branch `codex/web-apparatus-collections-20261014`. Exact implementation revision, immutable browser reports, artifact identities and command evidence are recorded in [PADDON_LABEL_SETTINGS_VERIFICATION.json](PADDON_LABEL_SETTINGS_VERIFICATION.json).

The existing `/app/paddons` detail now opens a native QR report, a scannable preview, downloadable standalone label HTML, and a label window with an explicit browser-print button. Native `/paddons/qr/report` preserves the exact five-digit QR payload and opaque paddon identity. QR Model2 uses numeric encoding, H error correction, black modules and a four-module white quiet zone. Leading zeroes are retained. The product weights come from the report; unknown weights stay unknown and received goods use native frozen weights. The native offline preparation metadata's `1 dona` quantity is never presented as product kilograms.

`Yorliqni tayyorlash` sends one native `/paddons/qr/print` request with explicit `print_transport: offline`; it prepares metadata without a printer command, job, print lock, membership or active-selection mutation. Fresh report validation rejects changed baselines before dispatch. Malformed or lost replies retain a session-scoped frozen intent for read-only recovery. No native driver, confirmation method or `/qr/confirm` call is implemented. `can_close_after_print` is native eligibility metadata, not a physical-print receipt.

The standalone label contains no ERP endpoint, token or callback. Opening it never calls `window.print`; a separate user click does. Opening/closing the browser print dialog changes only local text and never seals or marks the paddon printed. A blocked popup leaves download available. Labels use a 100×100 mm page with a 72 mm QR; operators choose paper/scaling/copies in their browser. Browser QA stubs `window.print` before any page loads and exercises both print and afterprint callbacks without producing physical jobs. Actual USB/Bluetooth/network printing, physical scanner acceptance and native sealing remain deferred.

The page header now opens ordinary S08 settings. GET retains the native OR capability guard. Only an actual administrator with `admin.access` and an actor reference may edit `free_movement_enabled`. PUT contains only that boolean; existing `worker_visibility_enabled` is shown as information and never edited. The explicit review covers eligible unreceived-roll transfer, printed-paddon editing and unlocking without lock ownership within existing visibility/write guards. Received goods remain protected. A fresh two-flag preflight blocks observed concurrent changes; native lacks CAS or a command receipt. A current matching read cannot prove a lost PUT. Current settings context is published in a layout effect after React commits, so discarded rendering cannot retarget an in-flight request. Dispatched operations are single-use and retain unknown outcomes after close/remount; recovery reads current state even when the connection is marked offline.

The active-paddon dialog now has a fixed header/footer, a scrolling body, smaller choices, a compact source summary and one visible operator explanation. Mutation guards and native output/selection semantics are unchanged. The primary actions and acknowledged status are kept inside the viewport; keyboard navigation scrolls the code field into view and closing returns focus to the trigger.

The full development gate passes 1,595 web tests across 85 files, 255 fixture tests, TypeScript and production/QA builds. New focused coverage includes 59 label API tests, 79 settings API tests, 9 independently decoded QR tests, 4 label component tests, 23 settings UI/controller tests, 13 pure label fixtures, 11 pure settings fixtures and 6 mounted integration cases. Independent pinned Sol 6.1/max review has no open P1/P2 after completing the unlock-effect copy. Focused lint has zero errors and four warnings: the existing initial handoff catalog synchronization, and a deferred settings predicate and draft-review synchronization safeguards. Exact final browser coverage and any limitations are retained in the verification record.

This is a supported W12 QR/label subset and the ordinary S08 free-movement subset. It does not certify physical output, scanning/sealing, the visibility-setting workflow, complete ERP parity or production readiness. Backend/mobile remain read-only. No production access, credential/access/security changes, native API edits, push, merge or deployment is in scope. The only new packages are pinned runtime `qrcode-generator@2.0.4` and dev decoder `jsqr@1.4.0`; all 549 pre-existing lockfile package entries remain unchanged, and the runtime MIT license is retained under `public/licenses`.
